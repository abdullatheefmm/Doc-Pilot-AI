DocPilot AI

Enterprise Knowledge Management System

An exhaustive breakdown of every feature, its theoretical purpose, and actual technical working.

Feature 1: Hybrid Retrieval Strategy

Purpose: To find the most relevant document chunks based on a user's question, handling both concepts (semantics) and exact words (keywords).

Theory

  • FAISS (Dense): Understands meaning. Matches "PTO" with "Vacation".
  • BM25 (Sparse): Understands exact keywords. Essential for finding specific product IDs or names.
  • RRF (Reciprocal Rank Fusion): A mathematical algorithm that merges the scores of both searches to rank the absolute best results.

Actual Working (Modules used)

Implemented in retrieval.py and embeddings.py.

  • The user query is vectorized using the local all-MiniLM-L6-v2 model.
  • FAISS executes a Cosine Similarity search on the vector DB.
  • BM25 executes a keyword frequency search.
  • The backend combines both arrays using the RRF formula to determine the final chunks.

Feature 2: Search Tuning (Top K & Similarity)

Purpose: Allows the user to control the strictness of the search and the amount of context fed to the AI.

Theory

  • Top K: Defines how many document snippets are retrieved. A higher K gives the LLM more context but increases latency and token costs.
  • Similarity Match: A threshold that acts as a filter. If a document's semantic score is below this threshold, it is discarded as "irrelevant."

Actual Working (Modules used)

Implemented in retrieval.py and App.jsx.

  • The React UI sliders send top_k and threshold integer/float values in the API payload.
  • The backend FAISS index returns results, but any result with a distance score below the threshold (e.g., 0.15) is dropped.
  • The list is sliced to top_k elements before sending to the LLM.

Feature 3: Knowledge Domains

Purpose: To logically partition enterprise data (e.g., Engineering, HR, Legal). This prevents the AI from mixing up "Company Policy" with "Technical Documentation".

Theory

  • Isolating the search space drastically reduces false positives (hallucinations).
  • It acts as a metadata filter applied before the vector search executes.

Actual Working (Modules used)

Implemented in knowledge_domains.py & KnowledgeBasePanel.jsx.

  • When a file is uploaded, it is assigned a domain tag in a SQLite database.
  • During retrieval, if a user selects "HR", the FAISS index generates an allowed_indices mask, ignoring all non-HR vectors during the search calculation.

Feature 4: File & URL Ingestion

Purpose: The pipeline for ingesting raw unstructured data into the RAG system.

Theory

  • Raw files or websites cannot be directly read by a vector DB.
  • They must be parsed into pure text, then chunked into overlapping segments (to preserve sentence boundaries), and finally vectorized.

Actual Working (Modules used)

Implemented in ingestion.py & chunking.py.

  • The FastAPI endpoint receives a PDF or URL.
  • Text extractors pull the raw text, which is passed to smart_chunk_text().
  • It breaks the text into 500-token blocks with a 50-token overlap, then regenerates the FAISS index.

Feature 5: RAG Chat Generation

Purpose: To synthesize a conversational, plain-English answer based only on the retrieved document chunks, preventing AI hallucinations.

Theory

  • Standard LLMs hallucinate facts. RAG forces the LLM to act as an "open-book test" taker.
  • The prompt specifically forbids the AI from using its internal training data.

Actual Working (Modules used)

Implemented in rag_qa.py using the Groq API.

  • The system wraps the retrieved chunks and the user's question into a strict prompt.
  • It calls the llama-3.3-70b-versatile model via Groq's LPU hardware for instant inference (~800 tokens/sec).
  • The response is streamed back to the React UI.

Feature 6: Enterprise Analytics

Purpose: To provide administrators observability into system health, user behavior, and LLM performance (latency/confidence).

Theory

  • Tracking "Average Confidence" shows if the database lacks answers.
  • Tracking "Response Time" monitors API health.
  • Tracking "Top Referenced Documents" shows what knowledge is most valuable to employees.

Actual Working (Modules used)

Implemented in analytics.py & AnalyticsPanel.jsx.

  • Every API call to /ask logs metadata (time taken, FAISS similarity score, target domain, chunks used) into a local SQLite database.
  • The React frontend fetches these aggregates and renders them using graphical chart libraries.
