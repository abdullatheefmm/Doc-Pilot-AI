7.2 – MODULE DESCRIPTION

7.2.1 DOCUMENT INGESTION MODULE

The document ingestion module is responsible for collecting and importing knowledge documents into the system. It supports two ingestion methods: automated web scraping of online documentation pages using BeautifulSoup4 with HTTP requests, and manual file upload through the API supporting PDF, TXT, and Markdown file formats. For PDF files, the module uses PyPDF to extract text content from each page. The ingested content is cleaned, normalized, and stored as plain text files in the knowledge base directory. This module forms the entry point of the entire RAG pipeline, ensuring that raw documentation is converted into a consistent format suitable for downstream processing and indexing.

7.2.2 TEXT PREPROCESSING & CHUNKING MODULE

The text preprocessing and chunking module transforms raw document text into structured, manageable segments for embedding generation. It first normalizes whitespace by stripping leading and trailing spaces from each line and removing empty lines. The cleaned text is then split into overlapping chunks using a sliding window approach with a configurable chunk size of 220 words and an overlap of 40 words. The overlap ensures that contextual information at chunk boundaries is preserved, preventing loss of meaning when sentences span across chunk edges. Each chunk is indexed with its source document name and sequence number, enabling accurate source attribution during retrieval and citation.

7.2.3 EMBEDDING GENERATION MODULE

The embedding generation module converts text chunks and user queries into dense numerical vector representations using the all-MiniLM-L6-v2 sentence transformer model. This pre-trained model captures semantic meaning, context, intent, and relationships between words, producing 384-dimensional embedding vectors for each input. The embeddings are L2-normalized to enable cosine similarity comparisons via inner product operations. This module is critical to the system's ability to perform semantic search — it allows the retrieval engine to match user queries against document chunks based on meaning rather than exact keyword matching, significantly improving the quality and relevance of search results.

7.2.4 VECTOR STORAGE & RETRIEVAL MODULE

The vector storage and retrieval module manages the FAISS (Facebook AI Similarity Search) vector index, which stores all document chunk embeddings for high-performance similarity search. During indexing, normalized embeddings are added to a FAISS IndexFlatIP (Inner Product) index, and the index along with document metadata is persisted to disk using pickle serialization. During query time, the module encodes the user's query into an embedding, performs an approximate nearest neighbor search against the index, and returns the top-K most similar chunks that exceed a configurable similarity threshold. The module also provides document inventory management, listing all indexed files with their sizes and indexing status.

7.2.5 RAG QUESTION-ANSWERING MODULE

The RAG (Retrieval-Augmented Generation) question-answering module is the core intelligence engine of the system. It orchestrates the complete pipeline from query understanding to grounded answer generation. The module performs intent detection to classify queries as "explain," "compare," or "summarize" types. It implements context-aware query rewriting to resolve pronouns and references from conversation history, improving retrieval accuracy for follow-up questions. Retrieved chunks are assembled into a structured prompt with source citations, conversation history, and strict grounding instructions. The prompt is sent to the Groq API running LLaMA 3.3 70B Versatile model with low temperature (0.2) for deterministic, factual responses. The module computes a confidence score based on average similarity of retrieved chunks and returns the answer with inline citations, source references, and metadata.

7.2.6 API GATEWAY MODULE

The API gateway module is developed using FastAPI and served through Uvicorn, providing the RESTful interface between the frontend application and all backend services. It exposes endpoints for question answering (/api/ask), document upload (/api/upload), document management (/api/documents), conversation history retrieval (/api/history), and user feedback submission (/api/feedback). The module implements CORS middleware for cross-origin requests, admin password authentication for document upload and deletion operations, session-based conversation tracking, and comprehensive error handling with appropriate HTTP status codes. It initializes the FAISS index and feedback database on application startup.

7.2.7 FEEDBACK & ANALYTICS MODULE

The feedback and analytics module enables users to rate the helpfulness of each assistant response, creating a continuous feedback loop for system evaluation. User feedback — including the session identifier, message ID, original query, generated answer, and helpfulness rating — is stored in a SQLite database with timestamps. The module provides an export endpoint that returns all collected feedback records in reverse chronological order, enabling administrators to analyze response quality, identify areas for improvement, and track user satisfaction trends over time. This data-driven approach supports iterative refinement of the knowledge base and retrieval parameters.

7.2.8 FRONTEND VISUALIZATION MODULE

The frontend visualization module is developed using React 19 and Vite 7 to provide a modern, responsive single-page application for interacting with the knowledge assistant. It features a real-time chat interface with message threading, typing indicators, and markdown-rendered responses. The sidebar includes configurable RAG settings with sliders for Top-K chunks and similarity threshold, suggested questions for quick exploration, and a knowledge base manager with categorized document listing. The module supports drag-and-drop document upload with admin authentication, dark and light theme switching with persistent preferences, and a per-message feedback system with thumbs up/down buttons. An insight ribbon displays live confidence scores, detected intent, and query rewrite information for each response, providing transparency into the RAG pipeline's decision-making process.
